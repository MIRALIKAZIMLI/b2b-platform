## Amaç

Platform admini tek istekle toptancıyı açar: işletme, `seller` yeteneği (`approved`), seçilen planın aboneliği, satıcı profili, hizmet bölgeleri, işletme admin rolü ve 7 günlük aktivasyon daveti **tek işlemde** oluşur; yetkilinin telefonuna bağlantılı SMS gider. Yetkili OTP ile girip daveti kabul edince işletme admini olur. Süresi dolan davet geçersizdir; admin yenisini gönderir. Ekranlar F2.1b'de.

## Yapılacaklar (dosyalar)

**Belge önce (aynı PR):**

- `openapi.yaml`:
  - `POST /api/v1/admin/sellers` → `201` gövdesi `{ businessId, invitationExpiresAt, activationSmsSent }`; hata `409 VOEN_ALREADY_REGISTERED`, `422 VALIDATION_FAILED`, `403`.
  - `GET /api/v1/admin/sellers` → liste öğesi `{ id, legalName, voen, regionId, status, createdAt, activation: pending | accepted | expired }` (sayfalama mevcut `Cursor`/`Limit`).
  - **Yeni:** `POST /api/v1/admin/sellers/{id}/activation` — yeni aktivasyon daveti gönderir (US-009 AC3); `200 { invitationExpiresAt, activationSmsSent }`; işletmede aktif admin üyelik varsa `409 INVALID_STATE_TRANSITION`.
  - `GET /api/v1/admin/plans` yalnızca okuma (F6.3'ün `POST`'u ve plan yönetimi F6.3'te kalır; form plan seçebilsin diye öne alındı — K5).
  - `POST /api/v1/team/invitations/accept` → `200 { businessId }`; geçersiz/süresi dolmuş/kullanılmış/başka telefon → `404 NOT_FOUND`.
- `user-stories.md` US-017 tablosu + `packages/shared/src/settings.ts`: `invitation.seller_activation_days` = 7 (tamsayı, 1–30). data-model `invitations.expires_at` notu "ayar: `invitation.seller_activation_days`" olur.
- `environments-cicd.md` §5: `WEB_BASE_URL` (SMS'teki bağlantının web adresi; local varsayılan `http://localhost:3000`). `env.ts`'e eklenir. `.env.example`'a dokunulmaz (proje kuralı); PR açıklamasında kullanıcıya yazılır.
- `c4-component.md` §5 altına "Platform rolleri ve admin uçları" tablosu (S1 kararı).
- S2 = A ise `productreport.md` D18 satırı güncellenir (faz spesifikasyonu §7.2).

**Kod:**

- `apps/api/src/modules/platform-admin/` (yeni modül): `sellers.controller.ts`, `sellers.service.ts`, `platform-admin.module.ts`, `index.ts`. Uçlar `@RequirePlatformRole(<S1>)`.
- `sellers.service.create`: **tek `withPlatformTx`** içinde (R15):
  1. Doğrulama: `planId` aktif ve `seller` planı; `regionId` ve `serviceAreaRegionIds` aktif bölgeler; `currency` aktif para birimi; `timezone` geçerli IANA adı; `voen` biçimi (`shared/voen.ts`).
  2. `businesses` (`created_via = admin`, `status = active`, `legal_type` VÖEN'den), `business_capabilities` (`seller`, `approved`, `approved_by` = admin, `approved_at` = `Clock`), `seller_profiles` varsayılan satırı, `service_areas`.
  3. `subscriptions` (seçilen plan; dönem başlangıcı/bitişi `PlanService` kuralıyla; F1.4b R14).
  4. `seller_business_admin` şablonundan işletme rolü (rol + izinler) ve şablona bağlı unvan.
  5. `users`: telefonla kullanıcı yoksa `full_name = ownerName` ile oluşturulur, varsa aynen kullanılır (S3 = A).
  6. `invitations`: telefon, rol, unvan, `token_hash` (SHA-256), `expires_at = now + invitation.seller_activation_days`, `created_by` = admin.
  7. Audit `seller.created` (🔒 alanlar maskeli; token yok).
  Diğer modüllerin yazma işlemleri `index.ts`'ten verilen, `tx` alan fonksiyonlarla yapılır (modüller arası doğrudan tablo erişimi yok).
- SMS işlemden **sonra** eşzamanlı gönderilir (K3): `SmsMessage.purpose` `'otp' | 'invitation'` olur; metin `sms.seller_activation_body` (3 dil, `{link}`; işletmenin `default_language`'ı, yoksa `az`); bağlantı `WEB_BASE_URL/<dil>/activate?token=<token>`. Gönderim hatası işlemi geri almaz: yanıt `activationSmsSent: false`, admin "yeniden gönder"i kullanır. `sms.daily_cap` ve `sms.allowed_country_codes` uygulanır.
- `POST /admin/sellers/{id}/activation`: aynı işletmenin açık davetlerini geçersiz kılar (`expires_at = now`), yenisini oluşturur, SMS gönderir. Audit `seller.activation_resent`.
- `GET /admin/sellers`, `GET /admin/plans`: `withPlatformTx` okuma.
- **Davet kabulü** `POST /api/v1/team/invitations/accept` (`modules/access`, `@Authenticated()`): token → SHA-256 → `invitation_accept(p_token_hash, p_user_id)`.
- `apps/api/drizzle/0013_invitation_accept.sql`: `invitation_accept` `SECURITY DEFINER` fonksiyonu (`migrator` sahipli; `SET search_path = pg_catalog, public, pg_temp`; `REVOKE ALL … FROM PUBLIC`; `GRANT EXECUTE … TO app_user`). Davet satırını `FOR UPDATE` kilitler; süresi dolmamış, kabul edilmemiş ve `users.phone_e164` davetteki telefonla aynıysa `memberships` (aktif, davetin rolü/unvanı) ekler, `accepted_at` yazar, `business_id` döner; aksi hâlde hiçbir şey yazmaz ve boş döner (→ `404`). Kullanıcı zaten o işletmenin üyesiyse `404`. Audit `invitation.accepted`.
- `regions` seed'i: onaylı pilot listesi [F2-seed-listeleri.md](F2-seed-listeleri.md) §1 (`pnpm db:seed`, tekrar çalıştırılabilir; testler kendi bölgelerini kullanır).
- Çeviri anahtarları: `sms.seller_activation_body` (az/ru/tr taslak).
- `endpoint-access.test.ts` yeni uçlarla güncel; `CHANGELOG.md`; `docs/ai-context.md` (bitmiş adım + K1–K6).

## Kararlar (bu kart için verilmiş)

- **K1** Davet kabulü `SECURITY DEFINER` fonksiyonla (R17); platform bağlamı yalnız `platform-admin` uçlarında.
- **K2** Kabul için oturumdaki kullanıcının telefonu davetteki telefonla aynı olmalı (R16). Her başarısız durum aynı `404`; yeni hata kodu yok.
- **K3** Aktivasyon SMS'i işlem commit'inden sonra eşzamanlı gönderilir (OTP SMS'i gibi; integrations §2). Outbox kullanılmaz: ham token yalnızca istek anında bilinir ve outbox yüküne token yazılmaz (F1.2b K7).
- **K4** R12 bu uçta kabul edilir: yeniden deneme ikinci işletme açamaz (VÖEN benzersiz → `409`).
- **K5** `GET /admin/plans` (yalnız okuma) F6.3'ten öne alındı; plan yönetimi F6.3'te.
- **K6** Süre `invitation.seller_activation_days` ayarından (AGENTS kural 6); varsayılan 7.
- **S1 = A:** uçlar `@RequirePlatformRole('super_admin', 'operations')`.
- **S2 = A:** aktivasyon SMS'i gönderilir (D18 güncellendi).
- **S3 = A:** yetkilinin kullanıcı kaydı admin açarken oluşur.
- **S7 = A:** aynı VÖEN herhangi bir işletmede varsa `409 VOEN_ALREADY_REGISTERED`.
- (Platform sahibi kararları, 2026-10-31; faz spesifikasyonu §4.)

## Emin olunmayan noktalar

1. Modüller arası `tx` geçirme kalıbı (R15): `businesses`, `billing`, `access`, `identity` modüllerinin `index.ts`'ten hangi fonksiyonları açacağı. Usta planda listeler; `withPlatformTx` başka modülde açılmaz.
2. Abonelik dönemi: `current_period_start` / `current_period_end` belgede net değil (plan dönemi, işletme saat dilimindeki bugün). Usta `PlanService` ve state-machines §8'e bakar, yoksa planda sorar.
3. İşletme `default_language`: istekte yok; Usta önerisi platform varsayılan dili (`languages.is_default`).
4. `applicationId` alanı (F2.2): bu adımda yok sayma mı `422` mi — planda.
5. Mevcut kullanıcının (S3) `full_name`'i `ownerName`'den farklıysa: dokunulmaz (kullanıcının kendi verisi).
