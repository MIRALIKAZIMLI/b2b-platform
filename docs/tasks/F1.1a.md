## Amaç

Bütün modüllerin kullanacağı tek güvenli veritabanı kapısını kurmak: her sorgu bir işlem (transaction) içinde, işlemin başında kiracı kimliği (`app.business_id`) ve kullanıcı kimliği (`app.user_id`) ayarlanmış olarak çalışır; PostgreSQL RLS (satır düzeyi güvenlik) başka kiracının satırlarını gizler.

## Yapılacaklar (dosyalar)

- `apps/api/src/core/db/client.ts` — `pg` havuzu + Drizzle örneği. Modüllere dışa açılmaz (yalnızca `core/db` içinden kullanılır).
- `apps/api/src/core/db/with-tenant-tx.ts` — `withTenantTx(ctx, fn)`: işlem açar, `app.business_id` ve `app.user_id` değerlerini **parametreli** `set_config(..., true)` ile (yani `SET LOCAL` etkisiyle) ayarlar, `fn(tx)` çağırır, commit / rollback.
- `apps/api/src/core/db/with-platform-tx.ts` — `withPlatformTx(ctx, fn)`: aynı, ek olarak `app.is_platform = 'true'` (data-model §1.1).
- `apps/api/src/core/db/index.ts` — yalnızca `withTenantTx`, `withPlatformTx` ve tipleri dışa açar.
- `apps/api/drizzle.config.ts` — Drizzle Kit yapılandırması, migration klasörü `apps/api/drizzle/`.
- `apps/api/drizzle/0000_roles.sql` — `app_user`, `migrator`, `readonly` rolleri. **Şifre içermez** (bkz. Kararlar K2).
- `apps/api/test/db.ts` — test veritabanını başlatan yardımcı (yerelde `@testcontainers/postgresql`, CI'da servis container'ı); migration'ları `migrator` ile uygular; testlere `app_user` bağlantısı verir.
- `apps/api/test/isolation.ts` — iki kiracı (A, B) bağlamı üreten yardımcı.
- `apps/api/src/core/db/__tests__/with-tenant-tx.test.ts`, `rls.isolation.test.ts`
- `packages/shared/src/env.ts` — **yalnızca** `DATABASE_URL`, `DATABASE_MIGRATOR_URL`, `DB_POOL_MAX` için Zod şeması (ilk hâli; F1.2 genişletir). Bkz. Kararlar K4.
- `.env.example` — yukarıdaki değişkenler, yerel örnek değerlerle (gerçek şifre yok).
- `package.json` (kök) ve `apps/api/package.json` — `db:migrate`, `test:isolation` betikleri (AGENTS.md "Komutlar").
- `CHANGELOG.md` — tek satır.

## Emin olunmayan noktalar (Usta planında bunlara cevap önermeli, uydurmamalı)

1. `ctx` tipi: önerim `{ businessId: string; userId: string | null }` (kiracı) ve `{ userId: string }` (platform). `withPlatformTx` `app.business_id` ayarlar mı? Belgede yok — planda sor.
2. Tablo izinleri (GRANT): S sınıfı tablolarda "uygulama rolünün doğrudan okuma izni yok" (data-model §1.1). Bu yüzden `ALTER DEFAULT PRIVILEGES` ile `app_user`'a toptan izin vermek yerine her migration'da tablo bazında `GRANT` önerilir. Planda netleştir.
3. Testcontainers yerelde Docker gerektirir; CI'da servis container'ı mı, Testcontainers mı? tech-stack.md §7: "CI servis container'ları; yerelde Testcontainers". `test/db.ts` ikisini de desteklemeli.
4. `withPlatformTx`'in yalnızca `platform-admin` modülünden çağrılması (coding-guidelines §3.7) bu adımda lint ile zorlanmaz; hangi adımda zorlanacağı belgede yok — not düş, Mimar'a sor.
